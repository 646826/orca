## Scope limits

Live supervised-worker ownership transfer, hidden provider reasoning transfer and cross-host migration are outside the first release. Switches must refuse unsupported ownership/enforcement cases. Retention preserves available canonical captured bytes; pre-clipping spill capture is not implemented. Local archive deletion is not provider-side erasure. Unknown native occupancy, delivery acceptance or external side effects must remain explicitly unknown.

## Performance verification protocol (T37)

The [performance checkpoint report](native-conversation-performance-checkpoints.md) preserves both the failed 10,000-event pre-batching run and the improved but still failing bounded replay run, with their distinct measurement methods. Its separate call-level diagnostic identifies synchronous scratch and source transactions but does not establish their OS-level cause. No responsiveness pass is inferred from integrity or memory results; the worker-boundary follow-up is a proposal, not an implemented fix.

The proposed gates below are acceptance targets, not measured guarantees. Run three warmups and ten measured repetitions on the same machine, runtime and fixed commit. Record the fixture seed, source commit, operating-system peak RSS, event-loop delay distributions and raw timings. Do not force garbage collection during the measured workload. Compare existing journal read/reduction against the same fixture; there is no upstream switching implementation to use as a switching baseline.

| Workload                                                                       | Proposed gate                                                                                                 |
| ------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------- |
| 1,000 / 10,000 / 100,000 events averaging 1 KiB, with tool pairs and revisions | Incremental peak RSS at most 128 MiB; event-loop p95 at most 50 ms and p99 at most 100 ms                     |
| One 64 MiB captured inline result, including Unicode                           | Same memory and event-loop gates; exact byte count and SHA-256; no shortened successful export                |
| Immutable artifact stores of 0 / 100 MiB / 1 GiB                               | Memory growth from 100 MiB to 1 GiB at most 32 MiB; exact byte count and SHA-256                              |
| 200-item timeline pages                                                        | Page latency p95 at most 200 ms and at most 1.2 times the matching baseline; cold first page at most 1 second |
| Cancellation during preparation/export                                         | Cancellation dispatch at most 250 ms; export cleanup at most 1 second; no leaked temporary claims             |
| 100 repeated activations                                                       | Retained heap growth at most 32 MiB after settling; no duplicate user dispatch or tool replay                 |

An explicit resource refusal preserves the original evidence and is preferable to a false successful transfer, but a refusal does not pass the advertised large-history workload. Failed gates must remain visible until the implementation or an explicitly reviewed requirement changes. UI paging, actual activations and model-quality evaluation require separate measurements from byte export.
